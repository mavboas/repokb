# Adapter Generation

This reference is loaded when running `emit-adapters` or when something
seems wrong with a tool-specific instruction file.

## What an adapter does

An **adapter** renders the canonical `SKILL.md` (at the repo root) into a
tool-native instruction file. One source of truth, four output formats.

```
                       SKILL.md  (canonical, with placeholders + TOOL blocks)
                            │
                            ▼
                    parse_skill_blocks()
                            │
              ┌─────────────┼─────────────┬─────────────┐
              ▼             ▼             ▼             ▼
      ClaudeAdapter   CodexAdapter   CopilotAdapter   CursorAdapter
              │             │             │             │
              ▼             ▼             ▼             ▼
         CLAUDE.md    AGENTS.md   copilot-      .cursor/rules/
         (root)       (root)      instructions  repokb.mdc
```

All adapters are **pure**: same canonical input + same context = byte-identical
output. This is what makes idempotency and drift detection possible.

## Canonical placeholders

The canonical SKILL.md uses two mechanisms:

### Simple substitution: `{{NAME}}`

| Placeholder | Filled with |
|---|---|
| `{{TOOL_NAME}}` | adapter key: `claude`, `codex`, `copilot`, `cursor` |
| `{{TOOL_DISPLAY}}` | human-readable: `Claude Code`, `OpenAI Codex CLI`, `GitHub Copilot`, `Cursor` |
| `{{INVOCATION_HINT}}` | per-tool one-line description of how the skill activates |
| `{{MAX_CONCEPT_TOKENS}}` | from `RenderContext` (default 1500) |
| `{{MANIFEST_TOKEN_CAP}}` | from `RenderContext` (default 3000) |
| `{{SKILL_VERSION}}` | `v2` (current spec version) |

### Conditional blocks

```markdown
<!-- TOOL:only name="claude" -->
This block survives ONLY for the Claude adapter.
<!-- TOOL:end -->

<!-- TOOL:except name="copilot,cursor" -->
This block survives for everyone EXCEPT Copilot and Cursor.
<!-- TOOL:end -->

<!-- TOOL:override name="codex" -->
This block REPLACES the immediately preceding paragraph for the Codex adapter.
For other tools, the original paragraph survives unchanged.
<!-- TOOL:end -->
```

Comma-separated tool lists allowed. Names match the registry keys.

## Per-tool conventions

| Tool | Output | Frontmatter | Merge | Critical banner |
|---|---|---|---|---|
| `claude` | `<repo_root>/CLAUDE.md` (project-level) | YAML `name:` + `description:` | sentinel | no |
| `codex` | `<repo_root>/AGENTS.md` | none | sentinel | yes |
| `copilot` | `<repo_root>/.github/copilot-instructions.md` | none, ≤ 3K tokens | sentinel | yes |
| `cursor` | `<repo_root>/.cursor/rules/repokb.mdc` | MDC: `description`, `globs`, `alwaysApply` | replace | yes |

The canonical `SKILL.md` (at the repo root) is the actual skill Claude's
loader picks up (with TOOL: blocks intact). `emit-adapters` writes a
**project-level** `CLAUDE.md` to the target repo so teammates get the protocol
via project guidance even without installing the skill globally — and so the
canonical stays untouched and re-renderable.

### Sentinel merge

For tools where users may have hand-written content in the target file
(`AGENTS.md`, `.github/copilot-instructions.md`), RepoKB content lives between
sentinels:

```markdown
(any user content above is preserved)

<!-- repokb:start version="2" -->
... RepoKB-generated content ...
<!-- repokb:end -->

(any user content below is also preserved)
```

`--mode=replace` overrides sentinel mode if you really want a full overwrite.

### Critical banner

Codex, Copilot, and Cursor get an imperative one-liner at the very top of the
file, prepended by the adapter:

> **CRITICAL: Do NOT load full source files when a concept contains
> `<<source:>>` directives. Use your file-read tool with offset+limit to
> load only the cited line ranges.**

Claude does not get this banner — its more careful instruction-following
makes the prose-style protocol enough.

## Drift detection

Every emitted file ends with a stamp:

```
<!-- generated by repokb emit-adapters@v2 from SKILL.md@<sha256>
     adapter: copilot CONVENTION_VERSION=2025-11; do not edit -->
```

- `<sha256>` is the first 12 hex chars of the canonical SKILL.md sha256.
- `CONVENTION_VERSION` is the adapter's target external-spec version.

The new `compile.py lint` rule **STRUCT-07** recomputes both and compares.
Mismatch = error.

## Upstream convention drift

External tools (Cursor, Copilot, Codex) change their instruction-file
conventions over time. Each adapter pins to a `CONVENTION_VERSION`:

```python
class CopilotAdapter(Adapter):
    convention_version = "2025-11"
    output_path_rel = ".github/copilot-instructions.md"
```

A local registry at `repokb/adapters/conventions.yaml` tracks what we
target. When an upstream changes:

1. Update the single adapter file (`repokb/adapters/<tool>.py`)
2. Bump its `convention_version`
3. Update `conventions.yaml`
4. Regenerate goldens: `REPOKB_UPDATE_GOLDENS=1 python -m unittest evals/test_emit_adapters.py`

## Graceful degradation

If an adapter's output path is unwritable (permission, missing parent dir
that isn't `.github/` or `.cursor/`), `emit-adapters` logs a warning and
skips that adapter — never aborts the whole run. Other adapters succeed.

## Pre-flight, dry-run, diff-only

`emit-adapters` always prints the paths it will write before writing. In a
TTY it prompts for confirmation; pass `--yes` to skip the prompt. Pass
`--dry-run` to skip writing entirely. Pass `--diff-only` to print a unified
diff against the existing files and exit with code 1 if any drift exists
(useful for CI).
